# Clamp Diagram Run 4 / Agent 3 Notes

## 1. Parametric Trusted Text-Geometry Architecture

`geometry.ts` exposes `buildGeometry(text: TrustedTextLayoutInput)` as the checked proof boundary. `TrustedTextLayoutInput` is not a string-width estimator. It represents boxes from a trusted external text layout stage: ink boxes, measured text boxes, or reserved layout boxes already chosen by some outside system.

The input contains width/height boxes for title, formula chain, column titles, assumption notes, ordered region labels, ordered formula cards, inverted empty/final/guide labels, the inverted formula card, threshold tick labels, the z-axis label, the C-axis label, and the bottom key-point note.

The `given text.*.width/height` lines define the supported envelope. Label/card geometry is derived from those trusted boxes plus padding, for example `text.orderedMiddleRegionLabel.width + 16` or `text.invertedFormulaCard.height + 16`. There are no character counts, average glyph widths, baked string measurements, browser measurements, DOM/canvas measurements, screenshots, raster sampling, or Pretext measurements.

`exampleTrustedTextLayout()` is a concrete fixture of externally supplied/reserved boxes for emitting `diagram.svg`. It is checked by Freerange against the same input envelope. These numbers are not inferred from the current English strings.

Text in `diagram.svg` is clipped to the generated boxes. The geometry proof is therefore about the outer text boxes and graph objects; it does not claim that arbitrary dynamic/i18n/emoji/font-fallback text will fit inside a box. If text exceeds its trusted box, clipping prevents important overlap.

## 2. SVG Generation Link

`diagram.svg` is generated by running:

```sh
bun experiments/clamp-diagram/run-4/agent-3/geometry.ts
```

The renderer calls `buildExampleGeometry()`, which calls `buildGeometry(exampleTrustedTextLayout())`. This keeps the concrete SVG coordinates connected to the same geometry data that Freerange checks. The remaining intentional boundary is text shaping inside each trusted box, which belongs to the external text layout stage.

## 3. Browser/Pretext Note

No browser, headless browser, Playwright, DOM measurement, canvas measurement, screenshots, render sampling, raster image generation, or Pretext measurement was used. Static validation used XML parsing only.

## 4. Contract-Driven Design Log

The diagram uses two equal-width column panels, fixed plot boxes, and graph segments represented as numeric endpoints. The ordered column proves `yX < uX`, nonnegative region widths, lower plateau alignment, diagonal endpoint alignment, and upper plateau alignment.

The inverted column proves `uX < yX`, nonnegative support widths, semantic empty interval width `0`, the full-width final `C(z) = y` line, and the dashed `min(z, u)` guide staying below it in screen coordinates.

Text boxes are part of the proof as external geometry. Important labels, formula cards, tick labels, axis labels, notes, column titles, page title, formula-chain boxes, and the bottom key-point note are contained in their intended regions. Formula cards and tick labels have explicit non-overlap checks. The column titles are checked to end before the assumption notes begin. The formula-card row is derived from the plot bottom plus the reserved fallback-label envelope and a shelf gap; the column panels derive their bottom from the formula row. The ordered middle-region label has a fallback branch: if the trusted text box is too wide for the preferred middle band, it moves to a shelf below the plot and above the formula cards; Freerange proves the joined result stays contained.

## 5. Freerange Intervention Log

Freerange also surfaced the downstream call failure at `buildExampleGeometry()`.

Change made: Changed `exampleTrustedTextLayout().invertedGuideLabel.height` from `34` to `32`.

Outcome: The next check passed.

Classification: Reactive missing-precondition/concrete-input correction.

Change made: None.

Outcome: Verification complete.

Classification: Final verification.

Command: visual SVG inspection after Cheng noticed the column titles overlapping the subtitles.

Relevant finding: The raw SVG had `<text class="col-title" ... y="191">` while the checked note boxes began at `y = 180`. The column titles were not represented in `TrustedTextLayoutInput`, not returned from `buildGeometry`, and not mentioned in the contracts. Freerange therefore proved the note boxes but had no fact to prove about the column-title text.

Change made: Added `orderedColumnTitle` and `invertedColumnTitle` trusted text boxes, returned `ordered.columnTitle` and `inverted.columnTitle`, rendered them through `textCell`, moved note boxes to a checked lower row, and added `columnTitle.bottom <= note.y` contracts for both columns. The assumption notes now use wider reserved note cells rather than text-width estimates.

Outcome: The next check passed, and the regenerated SVG no longer has the column title/note overlap.

Classification: Root-cause proof-boundary correction.

Command: `bun run fr check experiments/clamp-diagram/run-4/agent-3/geometry.ts`

Relevant output: `fr check: 1 files, 282 pass, 0 fail, 29 unknown`

What it revealed: Moving the formula row and panel bottom to derived top-level constants made the proof opaque. Freerange could not see that `FORMULA_TOP`, `COLUMN_HEIGHT`, and `KEY_POINT_Y` were derived from the plot bottom, formula region, and panel content.

Change made: Moved the derivations into `buildGeometry`: `formulaTop` is computed from `orderedPlot.bottom`, the reserved fallback-label height, and a shelf gap; `formulaBottom`, `columnHeight`, and the key-point y position are then computed from that local geometry. Added the key-point trusted text box and contracts for panel bottom/key-point ordering.

Outcome: The next check passed with `fr check: 1 files, 313 pass, 0 fail, 0 unknown`, and the regenerated SVG now has tighter formula-card spacing plus the bottom key point.

Classification: Reactive proof-visibility correction.

Freerange could express and prove the trusted text-box envelope, trusted box padding, graph containment, endpoint alignment, region-width nonnegativity, formula-card non-overlap, tick-label non-overlap, panel-bottom derivation, key-point placement, and the ordered middle-label fallback branch.
